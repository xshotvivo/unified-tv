# UTV Requirements Engineering

## Workflow
1. Separate the user outcome from a proposed implementation.
2. Extract functional, quality, operational, security, privacy and compatibility requirements.
3. Mark MUST / SHOULD / COULD; identify exclusions and dependencies.
4. Write observable acceptance criteria with setup, action, expected result and failure behavior.
5. Cover normal, boundary, malformed, offline, timeout, cancellation, recovery and migration cases.
6. Link each requirement to a design element, test and evidence record.
7. Resolve conflicts by priority: safety/data integrity, reliability, compatibility, user control, performance, appearance.
8. Keep targets labeled D until measured.

## Output
Requirement register, scope/non-goals, traceability matrix, acceptance checklist, open questions and change impact.
