# UTV Context and Project Memory

## Workflow
1. Read existing README, roadmap, ADRs, module status and recent change records.
2. Separate stable facts, current state, decisions, hypotheses, targets and unknowns.
3. Update canonical documents rather than creating duplicate summaries.
4. Record source/date/commit/device evidence for claims.
5. Keep a concise handoff: goal, completed, changed files, tests, blockers, next exact action.
6. Preserve superseded decisions with status and rationale; do not erase history.

## Guardrails
No personal secrets, API keys, private playlist URLs or unnecessary personal data. Do not infer completion from discussion. Plans are not implementation evidence.
